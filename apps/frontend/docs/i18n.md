## Directory layout

```
apps/frontend/
├── messages/
│   ├── en.json   ← English (source of truth)
│   ├── es.json   ← Spanish
│   ├── fr.json   ← French
│   └── ar.json   ← Arabic (RTL)
└── src/
    └── i18n/
        ├── routing.ts    ← supported locales + defaultLocale
        └── request.ts    ← server-side message loading
```

All locale-aware pages live under `src/app/[locale]/`.

## Supported locales

| Code | Language | Direction |
| ---- | -------- | --------- |
| `en` | English  | LTR       |
| `es` | Spanish  | LTR       |
| `fr` | French   | LTR       |
| `ar` | Arabic   | RTL       |

RTL detection is exported from `src/i18n/routing.ts`:

```ts
import { isRTLLocale } from '@/i18n/routing';
```

## Adding a new string

1. Add the key to `messages/en.json` in the appropriate namespace.
2. Add the same key (translated) to every other locale file.
3. Use the key in the component via `useTranslations`:

```tsx
import { useTranslations } from 'next-intl';

export function MyComponent() {
  const t = useTranslations('myNamespace');
  return <p>{t('myKey')}</p>;
}
```

**Never** write a raw string literal inside JSX — the linter will warn:

```tsx
// ❌ Flagged by react/jsx-no-literals
<p>Welcome back!</p>

// ✅ Correct
<p>{t('welcomeBack')}</p>
```

---

## Adding a new locale

1. Add the language code to `routing.ts` → `locales` array.
2. Create `messages/<code>.json` with all keys translated.
3. If the language is RTL, add the code to `RTL_LOCALES` in `routing.ts`.

## Lint rule

`react/jsx-no-literals` is configured in `.eslintrc.js` as a **warning** to surface hardcoded text during development. It is intentionally not an error to keep the build unblocked while the full extraction is in progress.

To suppress a justified exception (e.g. a symbol or brand name):

```tsx
{
  /* eslint-disable-next-line react/jsx-no-literals */
}
<span>™</span>;
```
